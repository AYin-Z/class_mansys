# 助手训练计划 v2（2026-09-21 重订）

> **为什么重订**：v1 用 1800 条自建数据微调出的 LoRA，在 165 条评测上 98.2%（原版 92.1%），
> 但挂到生产实测**更差**——「张驭捷」只回报区队就停了，「把张驭捷的证明图片发给我」**编造了记录 id 88**。
> 根因两条：**训练数据是单轮"一句话一个工具"，评测又只断言第一步**。
> v2 的第一原则因此是：**先把尺子修好，修不好就不训。**

---

## 0. 先修尺子（不满足就不开训）· 0.5 天 · ¥0

| 要做的事 | 为什么 |
|---|---|
| **① 真实语料回归集**：把生产库里的 29 条真实提问原文（09-10 ~ 09-21）连同期望行为写入仓库 | 我们的合成用例是"照着想象写的"；真实用户说的是「头疼」「列一下」「张驭捷」这种半句话。这一条是 v1 翻车的直接原因 |
| **② 多步断言**：评测跑**真实 agent 循环**（现已有 `scripts/agent-probe.js` 可复用），断言"最终回复里出现查到的关键信息（id / 图片链接 / 姓名）"且"工具序列包含查找链" | 现在的 `run.mjs` 只发一轮、从不执行工具，**结构上测不到多步** |
| **③ 门禁写死** | 没有门禁的"改进了"等于自欺 |

## 1. 数据 v2：以真实语料为骨架 · 1.5 天

### 1.1 七类真实形态（附生产库里的原话）

| # | 形态 | 真实原话 | 期望行为 |
|---|---|---|---|
| 1 | **超短输入** | 「头疼」「早操假」「张驭捷」 | 结合上一轮或常识**先补全/先查**，不要回"请问要办什么业务" |
| 2 | **指代式追问** | 「列一下」「其中六区的单独列出来」 | 依赖上一轮结果继续操作，不是重新理解一句话 |
| 3 | **多步链路** | 「把张玉杰的证明图片发给我」 | 姓名→查人→查记录→取详情→渲染图片 |
| 4 | **错别字/近音** | 「张玉杰」（实为张驭捷）、「早集合」（早操） | 模糊匹配 + 复述纠正，或给候选 |
| 5 | **确认流** | 「确认执行」 | 承接待确认的写操作 |
| 6 | **专用码** | 「A3F5B9」「绑定28F375」 | 走绑定流程，不当成普通闲聊 |
| 7 | **情绪/越界** | 「袋子好是傻逼」「把全队积分统一改成 60」 | 稳住、不调工具；越权礼貌拒绝 |

### 1.2 样本构造（**一条样本 = 一个情景，不是一个句子**）

```
情景（多轮）：
  user: 列一下需要审批的请假
  assistant: [tool pending_leave_approvals]  → 11 条 …
  user: 其中六区的单独列出来          ← 真实用户真会这么说
  assistant: [tool company_leave_records {company_id: 6}] → …
  user: 张驭捷那条批了
  assistant: [tool approve_leave {id: 638}] → 已生成待确认操作
```

- 每个情景 2~4 轮；训练时**按轮拆成样本**（每条仍带完整工具表 → 序列不会爆），
  但**保留前序轮次作为上下文**，这样才学到"指代"和"多步"。
- 覆盖审计：**48 个工具每个 ≥5 条正例**（v1 有 25 个工具零样本，包括 `notice_detail`）；
  生成器里加一条自检，缺了就报错退出。
- 负例补齐：拒绝（越权/批量改分）、闲聊不调工具、追问（缺**用户才知道的**参数）、
  **不该追问的**（缺能自己查到的 id → 必须自己去查）。

### 1.3 验证集必须按"说法"切分

v1 的验证损失 0.0028 毫无意义——验证集是从**同一个生成器**随机切的，
同一句话的 60 种说法会被切到两边，等于背题。v2 按**说法/情景**切分（train 与 val 不共享说法模板）。

### 1.4 规模与 token 预算

| 项 | v1 | v2（目标） |
|---|---|---|
| 情景数 | 1800 条单轮 | 约 900 个情景 → 拆成 **约 3600 条样本** |
| 平均长度 | 7500 token（工具表 6176） | 约 8500（多带一轮上下文） |
| 每 epoch token | 13.5M | 约 30M |
| epoch 数 | 3（明显过拟合，loss→0.003） | **2**（数据更杂，配合说法切分的早停） |
| 总 token | 38.4M | 约 60M |

## 2. 训练配置 v2 · 1 夜

### 2.1 主要约束是序列长度（显存）

fp32 logits 峰值 ≈ `seq × 151936 × 4`：

| cutoff | logits 峰值 | 24G 4090 可行性 |
|---|---|---|
| 10240（v1） | 6.2 GB | 勉强（v1 首训就 OOM 过，靠 `expandable_segments` 救回） |
| 12288 | 7.5 GB | 危险 |
| 16384 | 10.0 GB | 基本不行 |

**方案（按推荐顺序）**

1. **拆短样本**（推荐）：情景按轮拆，每条样本只带必要的上文，控制在 10k 以内 → 沿用 v1 的 4090 配置与成本；
2. **开 liger kernel**：融合 CE，不 materialize fp32 logits，能省下大部分峰值（需先在实例上验证 Qwen3-VL 兼容性）；
3. 换 40G 卡（AutoDL A100）≈ ¥5-6/h，贵一倍但省心。

### 2.2 超参（v1 基础上）

| 项 | v1 | v2 | 理由 |
|---|---|---|---|
| LoRA rank | 16 | 16（先不动） | 多步是**行为**问题不是容量问题；先靠数据解决 |
| lr | 1e-4 | 1e-4 | 不变 |
| epoch | 3 | 2 | 数据更杂 + 说法切分验证集早停 |
| cutoff | 10240 | ≤10240（拆样本后） | 见 2.1 |
| eval/save | 每 200 步 | 每 150 步 | 样本变多，步数变多 |

### 2.3 开跑前必须先做的三次测量（v1 的教训）

1. **memtest**：喂**最长的那条**样本跑 1 个优化步（v1 就靠这个在烧 8 小时前拦住了问题）；
2. **20 步吞吐**：算出真实 tokens/s → 反推总时长与花费 → 再定 `AUTODL_TRAIN_CAP_SEC`；
3. **管线自检**：`bootstrap.sh` 会先同步仓库脚本（v1 踩过"远端脚本过期"的坑）。

## 3. 执行顺序与预算

| 阶段 | 内容 | 时间 | 花费 |
|---|---|---|---|
| P0 | 修尺子（真实语料集 + 多步断言 + 门禁） | 0.5 天 | ¥0 |
| P1 | 数据 v2（情景生成器 + 覆盖审计 + 说法切分） | 1.5 天 | ¥0 |
| P2 | 本地零成本预演：用 base 模型跑**新评测**，确认"多步"这项确实低 | 0.5 天 | ¥0 |
| P3 | AutoDL 训练 2 epoch（约 60M token ≈ 13 小时） | 1 夜 | **约 ¥30** |
| P4 | 验收（四条门禁）+ 灰度（`LOCAL_LLM_LORA` 开关，一行回滚） | 0.5 天 | ¥0 |
| — | **合计** | **约 4 天** | **¥30-60**（含一次失败重跑） |

## 4. 验收与灰度

1. 四条门禁全过才上生产；
2. 灰度：`LOCAL_LLM_LORA=…` 启动 → 用 `scripts/agent-probe.js` 把**真实语料回归集**跑一遍 → 再观察真实会话；
3. 回滚：去掉开关重启（10 秒）；
4. **v1 的教训写进验收**：单步指标好看但多步变差 → **多步不达标一律不上**。

## 5. 备选方案（很可能更划算，先评估再动手）

| 方案 | 成本 | 说明 |
|---|---|---|
| **确定性脚手架** | 1 天，¥0 | 与其教 4B 学会多步，不如在 harness 里兜：识别到"裸人名/裸类型"就先自动预取（名册→记录→详情）塞进上下文，再让模型组织回答。**v1 的经验是：提示词/目录层的修复比微调收益更大**（"先自查再问"那条规则直接修好了你投诉的两句） |
| **换更大底座** | 下载 6GB + 1 夜训练 | 本地已有 Qwythos-9B（非同类），Qwen3.5-9B 在单步上曾得 97.5%。多步规划对小模型本来就难，**先验证 9B 零样本是否已经会多步**，会的话"微调 4B 学会多步"这条路可能根本不值得走 |
| **名字模糊匹配** | 0.5 天，¥0 | 「张玉杰」→ 提示"你是不是要找**张驭捷**"（服务端做相似度），不需要训练 |

**不建议做的事**：在没有多步评测之前再训一轮；用现有单轮数据加大 epoch。

## 6. 决策点（需要你拍板）

1. **先做 P0+P1（修尺子 + 造数据）再决定要不要训**，还是直接跳到 P3？
2. 备选方案里，要不要**先花半天验证 9B 的多步能力**（可能直接省掉整轮训练）？
3. 脚手架方案（确定性预取）要不要一起做？它与训练不冲突，且**成本极低**。
