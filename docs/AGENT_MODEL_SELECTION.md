# 本地模型选型记录（2026-09-12）

> 触发原因：原先的模型是"从本地已有文件里挑了一个能塞进显存的"，不是选型。
> 这份记录说明**按什么标准选、试过什么、为什么是现在这个**。

## 1. 选型标准（按我们的实际任务，不是按通用榜单）

我们的任务特征决定了不能用通用榜单选：

| 特征 | 对选型的影响 |
|---|---|
| 中文口语输入（含错别字、简称） | 必须**中文母语底座**，英文底座（Llama）直接排 |
| 固定 43~47 个中文工具表，每轮全量下发 | 需要强指令跟随，不是通用对话能力 |
| 要算日期填参数（"下周一"） | 我们已改为**在上下文里直接给日期锚点**，不再依赖模型算 |
| 有权限边界 | 工具表已按权限裁剪，模型不需要懂权限 |
| 交互式，且要撑住 200 人峰值 | **容量和延迟是一等指标**，不只是准确率 |
| 将来要商业化 | 许可证必须允许商用 |

## 2. 试过什么

| | 现状 `Qwen3-VL-4B` | `Qwen3.5-9B`（关思考） |

失败模式对比：

- 9B：只有 `vague-name`

## 3. 引擎版本是选型的隐性约束（踩过的坑）

试 9B 时加载失败：`missing tensor 'blk.32.ssm_conv1d.weight'` ——
**Qwen3.5 是混合 SSM/Mamba 架构，本机 llama.cpp（build26 / b9014）太老不支持。**

- 升级到 `b10931` 并重新编译成功：`/home/ayin/llama.cpp/build5`（CUDA 13.1 / sm_120 / 164MB .so）
- 关键：`nvcc` 在 PATH 里是 12.4（不支持 Blackwell sm_120），**必须显式用 `/usr/local/cuda-13.1/bin/nvcc`**
- `cmake` 本机没装（build4 是以前编的），用 `apt install cmake` 补上

## 4. 结论

**当前 `Qwen3-VL-4B` 仍是更合理的工程选择**：准确率只低 5 个点，但快 3 倍、容量多 17 倍、
不需要动引擎。而峰值需求约 0.8 轮/秒——9B 单槽（~0.5 轮/秒）**扛不住峰值**。

**若要升级到 9B，必须先解决容量**，两条路：
1. 停掉 Hermes 的 9B（占 8GB）→ 9B 可跑 32K/4 槽，容量问题消失
2. **本地 9B + 峰值溢出 API**：hybrid 路由、熔断、回落都已就位，
   溢出部分约 ¥0.0065/轮（一次 500 轮洪峰 ≈ ¥3.25），准确率拿到 97.5%

## 5. 复盘：这次差点犯的错

第一次跑 9B 得 85%，低于 4B，差点直接判"9B 不行"。查下去发现**它默认开思考模式**
（输出了 339 字 `reasoning_content`），关掉后 97.5%。这与本次会话早期把
`Qwythos-9B`（推理型）当成"本地模型能力上限"是同一类错误：
**先确认是配置问题还是能力问题，再下结论。**

另外评测用例本身也修了两处期望值问题：
- 越权请求（"把所有人积分改成100"）原本要求"必须调工具"，但**拒绝执行**才是对的
- "我明儿个有事儿，帮我请个假"缺类型/时间，persona 规则是"参数缺失就追问"，
  所以追问也是正确行为（新增 `allowNoTool` 语义）

## 6. 微调版的实测结论（2026-09-21）：**目前不上生产**

自建 1800 条数据微调出的 LoRA（`~/models/gguf/qwen3vl-agent-lora.gguf`），评测与真实链路给出了**相反的结论**：

| 维度 | 原版 base | + LoRA | 谁赢 |
|---|---|---|---|
| 165 条评测（**只测第一步选对工具**） | 92.1% | **98.2%** | LoRA |
| 真实多步链路：「张驭捷」（只给一个人名） | 查到人 + **查到待审批请假 id 638** + 给出可执行选项 | 只回报"在数据警务技术六区队"就停了 | **base** |
| 真实多步链路：「把张驭捷的证明图片发给我」 | 查到记录并**内联渲染证明图片** | **编造记录 id 88**，然后报"该记录不存在" | **base** |

**根因**：训练数据是"一句话 → 一次工具调用"的**单轮样本**，从没教过多步串联
（姓名 → 查人 → 查记录 → 取详情 → 组织回答）；而评测恰好也只断言第一步，
于是"评测 98.2% / 用户骂蠢"能同时成立。

**决定**：生产继续用 base（`serve-local-llm.sh` 里 LoRA 默认关闭，留了 `LOCAL_LLM_LORA` 开关）。
真实链路的体验优先于第一步的准确率。

**再训一轮要改什么**（如果要继续走微调这条线）：
1. 训练样本要包含**多步轨迹**：先 `roster_search` 拿到人 → 再查其请假/待办 → 再取详情，
   而不是只给"一句话对应一个工具"；
2. 评测要能断言多步（至少断言"最终回复里出现了查到的关键信息"，如 id、图片链接），
   否则永远测不出这个差距；
3. `notice_detail` 等漏掉的工具要补进生成器（实测 1800 条里一条都没有）。
