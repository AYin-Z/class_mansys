审计方式：7 个并行只读审计切片（请假 / 班费 / 内容模块 / 横切安全 / 前端基础 / 前端页面 / 数据层与脚本）

## 0. 总体结论

系统**不是一堆零散 bug，而是 5 个系统性根因**外溢的结果（下面每个根因都能对上多条缺陷）：

| # | 根因 | 典型后果 |
|---|---|---|
| R1 | 早期「role>=1 就是管理员」的粗粒度判断，没跟上后来的权限矩阵/作用域体系 | 干部可改他人邮箱→验证码接管超管；跨区队审批、改删他人内容 |
| R2 | 「能看」与「能写」的作用域用同一个函数（`canAccessClassRecord` 是中队平行查看语义），写在读基本都做了、写大量遗漏 | 任一区队干部可改删他区队通知/公告/作业/班费/相册/积分 |
| R3 | 审计中间件把请求体全量入库，读取口又对全体干部开放 | 心理咨询、匿名建议被去匿名化（线上已有实证） |
| R4 | 「人数」口径三分裂：`COUNT(*) FROM users`（215） vs `member_type='student'`（205） | 大额报销投票门槛多 7 票且永久卡死、班费应收虚增 |
| R5 | 写库路径缺事务/状态机/幂等键，失败静默 | 先写后鉴权、重复提交、驳回后幽灵待办、半恢复备份 |

审计期间已修复并上线（见文末「已修复」），其余按 P0→P1 分批处理建议见 §4。

## 2. P1（按主题归并）

**权限与作用域**
- 角色写进 24h JWT 且中间件不查库（`services/authService.js:90-94`、`middleware/auth.js:12-18`、`shared/scope.js:20`）：被降级/移出的用户在令牌过期前保留旧权限。
- 写路径缺记录级作用域：作业批改（`HomeworkController.js:80-89`）、抽奖开奖（`LotteryController.js:69-87`）、擂台判定（`ChallengeController.js:93-181`）、相册审核（`AlbumController.js:161-197`）。
- 心理申请可见范围过宽（`routes/psychological.js:11,13`，`HANDLE_PSYCHOLOGICAL` 默认角色 1-9）。
- `/api/auth/find-by-student` 可枚举全校手机号/邮箱（`AuthController.js:288-298`，`_publicUser` 含联系方式）+ 登录报错差异化。
- 注册可自选区队（`AuthController.js:200-233`），注册即可读该区队通知/相册/公示。

**业务正确性**
- 作业截止后可提交且覆盖已批改分数/评语（`models/Homework.js:49-70`）。
- 抽奖可重复开奖/对已关闭活动开奖；擂台无唯一键、judge 不校验状态（可刷战绩、乱换擂主）。
- 三个角标计数无区队过滤（`models/Notice.js:68-77,126-132`、`models/Homework.js:100-111`）：红点数恒大于列表条数。
- 「逾期未销假」恒为 0：`models/Leave.js:126-131` 的 autoCancel 谓词与 `CompanyController.js:61-63` 的统计谓词完全相同。
- 「今天」用 UTC：`CompanyController.js:21,147` `toISOString().slice(0,10)` → 北京时间 00:00-08:00 查的是昨天（早操时段必现）。（本轮已修）
- 余额字符串拼接：`models/Fee.js:71-75` DECIMAL SUM 为字符串，`income + collected` 变成拼接（线上暂无「收入」行故为潜伏，`totalExpense` 已返回字符串）。
- 收缴口径混乱：`FeeCollection.js:7,17,30` 用全库人数；免缴写 `paid_at` 被计入已缴；重复缴纳覆盖金额而非累加；`collected_amount`（3685.80）与 0 条明细账实不符。
- 报销 `type` 无枚举校验（`FeeController.js:116`），批准了却不进任何口径。
- 驳回后残留 `status=0` 节点 → 幽灵待办（`ExpenseApproval.js:173-181` + `getPendingApprovals` 不过滤 `e.status`）。
- 已上线库大额审批链缺 step 2（`seed.js:157-159`）：680/2500 元报销永久卡死。

**数据与运维**
- 跨表写入无事务：`castVote`（票已投状态未落）、`createExpense`（INSERT→createChain→stampClassId 三次写库，失败留半成品且 `class_id IS NULL` → 全局可见）。
- `restore-db.js` 无库名白名单、无事务、时区敏感（TZ=UTC 机器恢复会让 TIMESTAMP 偏移 8 小时）——比测试夹具的护栏还弱。
- `setup-test-db.js` 可 DROP 任意库且迁移清单硬编码缺 015/016。
- 迁移语义非幂等：重跑 016 复活被撤销的权限；重跑 010 把有意为全局（class_id NULL）的内容重新打上区队标记。
- 备份不含视图/例程，恢复只覆盖 dump 内的表；保留策略硬编码库名。
- `user_stats` 视图 LEFT JOIN 交叉膨胀（实测 total_points=100，真值 50）。
- 缺失索引：`users.member_type`、`leaves(status,is_cancelled,end_time)`、`expenses(status/created_at)`、`fee_collection_records(paid_at)`、`notices(class_id,created_at)`。
- 缺失唯一约束：`homework_submissions(homework_id,user_id)`、`challenge_applications(challenge_id,user_id)`、`leaves` 同人同时段、`fee_collections` 同区同批次、`companies(name)`。
- `database_init.sql` 不可重复执行且与迁移脱节（缺 015/016/012/013 的表列）。
- `import-roster.js` 新建中队路径必失败（`companies.id` 为 VARCHAR 无自增）且会把所有区队 company_id 改写。

**前端**
- 请求层错误提示是死代码（`utils/request.ts` 调 `window.uni?.showToast`，全仓未定义）+ 33 处空捕获 → 失败静默。（本轮已修）
- 401 只清 token/profile，不清权限快照 → 换用户后沿用上一用户入口。（本轮已修）
- 超管后台 3 个导出按钮必然 401（`window.open` 不带 Authorization）。（本轮已修，改带鉴权 blob 下载）
- 路由守卫只看 `requiresAdmin`，权限矩阵在 UI 不生效；`fee/index.vue:13` 硬编码角色。
- `/pages/fee/approvals` 漏 `requiresAdmin`；`uploadFile` 无 401/进度；fetch 无超时。
- `types/roles.ts` 权限镜像与后端默认矩阵漂移且缺 10 个键。
- `utils/ui.ts` 用 rpx，浏览器全部丢弃（toast/确认弹窗排版塌）。
- agent 页流式失败留空气泡；SpeechRecognition 不 stop。

## 3. 已核对正常（可直接采信）

- SQL 注入面：全仓动态 SQL 片段只剩常量/白名单表列，用户输入全部 `?` 占位——无可注入点。
- XSS：4 处 `v-html` 全部经 `sanitizeHtml`/`renderMarkdown` 白名单，未发现 bypass。
- MCP/令牌链路：sha256 存储、可吊销、写操作两阶段、`agent_actions` 有 TTL 与归属校验，无 IDOR。
- 错误契约与 5xx 不泄堆栈；CORS 白名单、helmet、trust proxy、限流顺序正常。
- 请假/班费/通知等**只读**接口作用域基本齐全（与 E2E 断言一致）。
- 权限矩阵以 DB 为准并 30s 兜底刷新；防锁死保护有效。
- 迁移 005-016 的加列加索引均幂等（信息模式前置判断）；`migrate.js` 的 sha256 + dry-run 实现正确。

## 5. 需要产品决策的点

1. 「在编人数」口径：`left`/`staff`/`system` 是否计入任何分母（当前三种口径并存）。
2. 大额报销是否需要普通学员参与投票？若要，需要同时改权限矩阵、前端入口与阈值口径；若不要，删掉 step3 全员可见与相关注释。
3. 「中队内任一区队干部可平行管理」是否包含**写**（改删他区队内容）？当前只读做了作用域、写没做——需要明确边界。
4. 心理申请可见范围是否收窄为「心理副区/辅导员/超管」。
5. `id=34 殷政` role=8 且 member_type='student' 是刻意兼任还是导入残留；生产库冗余索引 `idx_test` 是否清理。
6. `UPLOAD_AUTH_MODE` 切 strict 的时机（旧 APK 覆盖率）。
