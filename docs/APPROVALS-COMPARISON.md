## 2. V2 页面（`approvals.vue`）功能覆盖情况

### 2.1 已覆盖的功能
| 旧功能 | 覆盖情况 | 差异 |
|--------|---------|------|
| F01 调用 `getPendingApprovals()` | ✅ 完整覆盖 | 同接口 |
| F08 显示用途 | ✅ | |
| F09 显示金额 | ⚠️ 有差异 | v2 使用 `(item.amount / 100).toFixed(2)`，旧版用 `Number(item.amount).toFixed(2)`。单位假设不同（分 vs 元） |

| F18 调用 `approveExpense`/`rejectExpense` | ✅ | |

## 3. 差距清单

### MISSING（缺失的关键功能）
| # | 功能 | 影响 | 说明 |
|---|------|------|------|
| M1 | **双 Tab（待审核 + 已处理）** | 无法查看历史审批记录 | 旧版可切换查看已处理项及其结果 |
| M2 | **已处理项结果展示** | 已处理的审批无处查看 | 包括通过/驳回状态 + 审批备注 |
| M3 | **下拉刷新** | 用户需手动刷新页面 | 旧版支持下拉刷新重载数据 |

### GAP（存在但实现不完整或有差异）
| # | 功能 | 旧版实现 | V2 实现 |
|---|------|---------|---------|
| G1 | **申请人显示** | `applicant_name \|\| student_id \|\| '未知'` | 仅 `applicant_name`（可能空白） |
| G2 | **详情字段** | 显示 `item.details` | 不显示 |
| G3 | **审批层级标签** | 完整链路描述（如"中额·区队长→辅导员"） | 仅三段式文字（"中额"） |
| G4 | **投票进度可视化** | 内联进度条 + 计数 x/19 | 无进度反馈 |
| G5 | **投票后阈值判断** | 检查 `thresholdMet` 就地更新 status | 直接移除列表 |
| G6 | **金额单位** | 以元为单位展示（`.toFixed(2)`） | 假设分为单位（÷100），需确认后端实际单位 |
| G7 | **驳回原因输入** | `uni.showModal` 可编辑弹窗 | 浏览器 `prompt()`（移动端体验差） |
| G8 | **通过确认** | 弹确认对话框 | 直接执行（误触风险） |

### MINOR（UI 视觉差异，不影响功能）
| # | 功能 | 旧版 | V2 |
|---|------|------|----|
| R1 | **卡片强调条** | 左侧彩色条（小/中/大色） | 无 |
| R2 | **空状态文案** | "暂无记录" | "暂无待审批事项" |
| R3 | **按钮样式** | uni-app rpx 样式 | CSS var 样式 |

## 4. 修复建议

### 4.1 高优先（MISSING）
| 建议 | 对应问题 |
|------|---------|
| **添加「已处理」Tab**：复用旧版逻辑，用 `status !== 0` 过滤已处理项，展示通过/驳回状态标签和审批备注 | M1, M2 |
| **添加下拉刷新**：在列表容器上绑定 `@scrolltolower` 或类似下拉刷新机制，调用 `getPendingApprovals()` | M3 |

### 4.2 中优先（GAP）
| 建议 | 对应问题 |
|------|---------|
| **申请人显示增加回退链**：改为 `item.applicant_name || item.student_id || '未知'` | G1 |
| **添加 `details` 字段渲染**：条件渲染 `item.details` | G2 |
| **还原审批层级标签**：用旧版的 `tierLabel()` 函数生成完整链路描述 | G3 |
| **添加投票进度条**：在内联区域或弹窗中添加进度条 + 计数 x/19 | G4 |
| **投票后处理 `thresholdMet`**：恢复旧版的阈值判断逻辑 | G5 |
| **确认金额单位**：与后端确认 amount 单位是分还是元，统一处理方式 | G6 |
| **驳回原因改用模态弹窗**：使用自定义弹窗代替 `prompt()` 以获得更好移动端体验 | G7 |
| **通过操作前加确认**：恢复确认对话框防误触 | G8 |

### 4.3 低优先（MINOR）
| 建议 | 对应问题 |
|------|---------|
| **还原彩色强调条** | R1 |

## 5. 总结

- **核心审批/投票操作（通过、驳回、投票）**：v2 已完整覆盖，API 调用一致
- **已处理项查看**：**严重缺失**（MISSING）— v2 仅展示待审核项，无法查看历史结果
- **用户反馈信息**：**多处缺失**（GAP）— 投票进度、详情字段、完整申请人信息、金额单位不一致均未处理
- **交互细节**：**退化**（GAP）— 通过无确认、驳回用 `prompt()` 替代模态框，移动端体验下降
- **UI 视觉**：**简化**（MINOR）— 去掉了彩色强调条等细节装饰

**总体结论**：v2 覆盖了约 **60%** 的旧版功能。核心增删改查操作齐全，但**已处理记录查看、下拉刷新、投票进度反馈**等关键用户体验功能缺失。建议按上述优先级逐步补齐。
